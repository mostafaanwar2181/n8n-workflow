Agent Workflow Flows

🔵 Pre-Visit Agent Flow

  • Form Trigger: Collect intake data (name, DOB, gender, phone, insurance, medical history)
  • Webhook: /webhook/pre-visit-intake (API access)
  • Mandatory Field Validation: Check all required fields present
  • Insurance Format Check: Regex ^POL-[A-Z]{2}-[0-9]{8}$
  • Conditional Logic: If female & age 15-55, check pregnancy status
  • Risk Score Calculator: Points-based scoring (hypertension+3, chest-pain+4, etc.)
  • Decision: Score ≥7 → Nurse Queue Escalation | Score <7 → Normal confirmation
  • Incomplete → Schedule 24h follow-up task (SMS, 2 retries)
  • Audit Log: INTAKE_RECEIVED, INTAKE_VALIDATED, ESCALATION_CREATED

🟢 Post-Visit Agent Flow

  • Form Trigger: Collect pain score (0-10), free-text symptoms, visit ID
  • Webhook: /webhook/post-visit-checkin (API access)
  • Input Validation: Verify patient ID, visit ID, pain score range
  • NLP Red-Flag Classifier: Groq LLM analyzes free text for 5 categories
  • Conflict Detection: High pain score + minimizing text → forced escalation
  • Emergency: Breathing/bleeding → immediate escalation (5 min SLA)
  • Clinical: High pain/fever/side effects → physician escalation (1 hr SLA)
  • Normal: Low pain, no flags → schedule 48h proactive check-in
  • Audit Log: RED_FLAG_DETECTED, ESCALATION_CREATED, CHECK_IN_LOGGED

🟠 Billing Agent Flow

  • Form Trigger: Collect patient ID, visit ID, treatment codes, amounts, policy info
  • Webhook: /webhook/billing-inquiry (API access)
  • FAQ Engine: Keyword-match against 8 billing FAQ categories
  • Duplicate Detection: Generate idempotency key (patient+visit+codes+date)
  • Insurance Expiry Check: Policy expiryDate vs current date
  • Coverage Matching: Treatment codes vs policy coveredCodes
  • SLA Tracking: Claims >30 days → auto-escalate to billing manager
  • Manual Override: Requires valid code + justification → audit trail
  • Audit Log: DUPLICATE_BLOCKED, SLA_BREACH, OVERRIDE_APPLIED

🟣 Retention Agent Flow

  • Form Trigger: Input patient data (or batch array) for retention scan
  • Webhook: /webhook/retention-scan (API access)
  • Inactivity Check: Last visit >6 months ago?
  • Auto-Segmentation: Classify by condition keywords (chronic/wellness/post-procedure/lapsed/at-risk)
  • Suppression Check: Block if unresolved clinical or billing issues
  • Consent Verification: messagingConsent must be true
  • Frequency Cap: Max 2 contacts/month per patient
  • Re-engagement: Send segment-appropriate message or suppress
  • Audit Log: RETENTION_OUTREACH_SENT, RETENTION_SUPPRESSED

🔴 Clinical Triage Agent Flow

  • Form Trigger: Collect patient symptom description (free text)
  • Webhook: /webhook/clinical-triage (API access)
  • Emergency Keyword Scanner: Check for 'chest pain', 'can't breathe', 'unconscious', 'heart attack', 'severe bleeding', 'stroke', 'seizure', 'choking', 'overdose'
  • If Emergency Keyword Found → IMMEDIATE escalation to emergency services (5 min SLA) — LLM bypassed entirely
  • If No Emergency → Send to Groq LLM Classifier (Llama 3.3 70B, temp 0.1)
  • LLM classifies: Emergency / Same-Day / Routine / Insufficient
  • Insufficient → Generate structured follow-up questions (never classify without enough info)
  • All responses include mandatory medical disclaimer — no diagnoses, no definitive advice
  • Audit Log: TRIAGE_EMERGENCY, TRIAGE_CLASSIFIED, TRIAGE_FOLLOWUP_QUESTIONS

Key Design Principles

Safety First: Emergency keywords bypass LLM — deterministic, zero-delay
No Hallucination: Clinical responses never diagnose or provide definitive medical advice
Idempotency: Composite keys prevent duplicate invoices, alerts, escalations
Audit Trail: Every action logged immutably — compliance-ready
SLA Enforcement: Tiered deadlines (5min → 48hr) with auto-escalation
Consent-Safe: No outreach without verified messaging consent
Deterministic Rules: Validation, scoring, and controls use rules engine — no AI
Graceful Fallback: LLM failure → manual review escalation with safe defaults
